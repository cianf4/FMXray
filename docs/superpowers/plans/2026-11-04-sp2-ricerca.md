# SP2 — Motore di ricerca: piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, inline (no subagents). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `fmxray search "age<22 pa>180" --career Roma` e le ricerche salvate funzionano sul save reale, con un albero di filtri del dominio compilato in Polars, export CSV e "nuovi risultati" tra snapshot.

**Architecture:** nuovo pacchetto `fmxray.domain.search` (albero Specification, compilatore Polars, parser a discesa ricorsiva, alias, campi calcolati). Casi d'uso `SearchPlayers`, `SaveSearch`, `RunSavedSearch`, export CSV in `application`; porta `SavedSearchStore` implementata in `adapters.sqlite_catalog` con la migrazione dello schema a v2.

**Tech Stack:** come SP1 (Python 3.14, Polars 2.1, sqlite3, pytest, Hypothesis). Nessuna dipendenza nuova.

**Spec:** [docs/superpowers/specs/2026-11-04-sp2-ricerca-design.md](../specs/2026-11-04-sp2-ricerca-design.md); in subordine la [spec madre](../specs/2026-11-03-fm-x-ray-design.md) §7.

## Global Constraints

- Valgono tutti i Global Constraints del [piano SP1](2026-11-03-sp1-fondamenta.md): chi esegue non lancia `uv sync`, `git commit` o `git push`, stampa i comandi completi (senza segnaposti e senza attribuzioni) e attende "fatto"; API di Polars verificate sulla versione installata.
- Branch di lavoro: `sp2-ricerca`, creato dall'utente da `main` aggiornato.
- Nessuna dipendenza nuova; `difflib` della stdlib per i suggerimenti.
- `fmxray.domain.search` importa solo stdlib, Polars e `fmxray.domain`.
- Soglie dei ruoli: `pos:` → `>= 15`, `natural:` → `>= 18`.
- Ricerca su 126.427 righe in meno di **200 ms**, escluso il caricamento.
- CSV: UTF-8 con BOM (`include_bom=True`), separatore `,`, liste unite con `|`.
- JSON delle ricerche salvate con `"version": 1`.
- Default di `search`: ordinamento `ca` decrescente, limite 50.

## Review Focus

1. **`not` su valori mancanti**: `not club:roma` deve includere gli svincolati (club vuoto); `transfer_value>1000000` deve escludere chi non ha valore → test in Task 1.
2. **Club con punti, virgolette e accenti**: `club:"A.S. Roma"`, `club:roma`, `name:"unal celik"` → stesso giocatore → test in Task 3.
3. **Ricerca vuota**: `""` → tutti i giocatori (ordinati e limitati), non un errore → test in Task 3 e Task 4.
4. **JSON di una ricerca salvata con versione sconosciuta o rovinato**: errore chiaro, nessun crash → test in Task 1 e Task 6.
5. **CSV con liste e accenti**: si riapre con gli stessi valori, liste come `AMC|STC` → test in Task 5.

Ogni foglia finisce con `.fill_null(False)` (così `Not` di un valore mancante è vero); `TextContains` usa la colonna `f"{field}__folded"` con `str.contains(text, literal=True)` (il testo arriva già normalizzato dal parser); `ListContains` usa `list.contains`; `IsNone` → `is_null()`; `MatchAll` → `pl.lit(True)`; campo assente dallo schema → `UnknownFieldError` con suggerimenti da `difflib.get_close_matches(field, schema.names(), n=3)`.
